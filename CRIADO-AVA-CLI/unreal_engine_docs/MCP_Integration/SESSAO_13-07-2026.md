## 3. Correções Críticas Aplicadas (AMBOS os Projetos)

### Bug #1: Deadlock por `Future.Get()` sem timeout

**Arquivo:** `EpicUnrealMCPBridge.cpp`
**Linha original:** `return Future.Get();`

**Problema:** `ExecuteCommand()` usa `AsyncTask(ENamedThreads::GameThread, ...)` + `Promise/Future` para executar comandos na Game Thread. O `Future.Get()` bloqueia a thread do servidor TCP **indefinidamente**:

```
Cliente TCP → Bridge → AsyncTask(GameThread) → Future.Get() ← BLOQUEADO
                                                       ↓
                              Novo cliente → Accept() ← NÃO CHEGA AQUI
```

Se o comando na Game Thread demora (ex: `construct_house` spawnando dezenas de atores) ou CRASHA (ex: null pointer, assertion), `Promise.SetValue()` nunca é chamado → **deadlock eterno** da thread TCP.

**Solução aplicada:** Timeout por categoria de comando

```cpp
// Timeout por categoria
DefaultTimeout     = 30.0s   // ping, create, compile, delete, spawn, attach, apply, set_*
InspectTimeout     = 120.0s  // read_*, analyze_*, get_*, list_*, search_*
ProceduralTimeout  = 300.0s  // construct_house, create_tower, create_wall, create_staircase

FString Result;
if (Future.WaitFor(FTimespan::FromSeconds(TimeoutSeconds)))
{
    Result = Future.Get();     // Comando completou
}
else
{
    // Timeout — retorna erro em JSON, thread liberada
    Result = {"status":"error", "error":"Command 'X' timed out after Ys on Game Thread. The server is ready for new commands."}
}
return Result;
```

**Efeito:** Se um comando travar a Game Thread, após o timeout a thread TCP é liberada e pode aceitar novos clientes. O comando travado continua rodando em background na Game Thread (sem bloquear mais ninguém).

### Bug #2: Backlog do listener pequeno (5 → 10)

**Arquivo:** `EpicUnrealMCPBridge.cpp`
**Linha alterada:** `NewListenerSocket->Listen(5)` → `NewListenerSocket->Listen(10)`

**Razão:** Quando comandos demoram, múltiplos clientes tentam conectar. Com backlog 5, o 6º recebe `ECONNREFUSED`. Com 10, até 10 conexões pendentes são aceitas pelo kernel enquanto a thread está ocupada.

### Impacto combinado

```
Antes:
  Comando lento na Game Thread → Future.Get() bloqueia → backlog 5 enche → ECONNREFUSED → deadlock

Depois:
  Comando lento na Game Thread → Future.Get() aguarda até timeout → retorna erro → thread liberada
  Comando normal → Future.Get() retorna em <1s → sem bloqueio
  Backlog 10 → tolera até 10 conexões em fila durante pico
```

### Enviar comando via Python
```python
import socket, json, time

def send_cmd(cmd, params=None, timeout=15):
    s = socket.socket()
    s.settimeout(timeout)
    s.connect(('127.0.0.1', 55557))
    payload = {'type': cmd}
    if params is not None:
        payload['params'] = params
    msg = json.dumps(payload) + '\n'
    s.sendall(msg.encode())
    time.sleep(1)
    data = b''
    while True:
        try:
            chunk = s.recv(65536)
            if not chunk: break
            data += chunk
        except socket.timeout:
            break
    s.close()
    return json.loads(data.decode())

result = send_cmd('get_command_schema')
print(json.dumps(result, indent=2))
```
